# ARC instruments: reference code and tests for the v1.93 guidance

Written 5 September 2026. Pure Python 3.9 with numpy and scipy; no network, no
model calls. This is a reference kit: the code that the v1.93 guidance says each
deciding instrument needs before its confirmatory run, written once, tested, and ready to be adopted
into the estate units by the applying session. The registration governs; where this code and the
registration disagree, the tests are the place the disagreement becomes visible, and the registration
is corrected or the code is.

Why it exists in this repository and not in the estate: on the model that wrote it, the preregistration
estate is a protected publication surface. The applying session copies each module into the unit that
decides the proposition, re-pins the hashes, and the estate copy becomes the registered one.

## Modules, and the guidance items they implement

The table has twenty-three rows: the twenty-two propositions and one labelled `ratio` row for the corrector-class ratio (an extension, not a proposition). ## What this kit is not

It is not a result about any AI system, not an instrument that has been run on real data, and not a
substitute for the identification argument P5's unit must write. The attacker in the provenance
challenge is a baseline (hashed character n-grams with a multinomial model), chosen so that a positive
control can be demonstrated without external dependencies; a deciding unit registers stronger attacker
classes beside it. Every threshold used here is the registration's or a placeholder named as such in the
docstring; the registration's numbers govern.

## Adoption path

1. The applying session runs the tests here, then copies the module a unit needs into that unit's
   `code/` folder and records the file hash in the unit's manifest.
2. The registration's prose verdict sentences are checked against `verdicts.scoring_table()`; any
   sentence that returns a different verdict for the test intervals is corrected.
3. The confusion matrix, precision and sign-power outputs are recorded as design sensitivity in the
   deciding unit before any data are collected, with the registered thresholds beside them.

## The runner (arc_runner, 5 September 2026)

The kit decides verdicts and simulates designs; it never touched a system. `arc_runner` is the other half: the code that runs P5 and P16. It has a model adapter with two implementations, a frozen hidden capability ladder, the revision loop with retention control and checkpoints, sealing with a pilot flag, the P5 crossed bank with seal-then-generate, the P16 driven titration with the registered detection rule, and a command line.

The mode is the command, and there are four of them: `demonstrate` (the simulated system), `smoke` (a real provider on the reference pool, for the wiring only), `pilot` (a real provider, for sizing, never scored) and `confirm` (the deciding run). There is no flag that turns one into another. A demonstration says in its manifest and at the top of every printed summary that its verdicts are simulated recoveries of a known test case; `confirm` refuses to start unless the domain ladder is a registered pool, the checkpoint store holds every state the bank will place AND is the store the loaders actually read, the loaders return the artefacts that store holds when they are asked for them, the configuration is resolved (against the rules of the experiment it belongs to, P5's or P16's), a P16 titration carries the five registered quantities its verdict will be read with, and the approved figure is held in a controller that reserves against it call by call rather than being a number in a record, and that refusal arrives before the adapter is constructed and therefore before anything is spent. The five quantities are the calibration uncertainty on the located boundary, the equivalence band on the sealed slope, the informative horizon, the practical-absence band and the across-window resolution; none has a default, they are supplied to `confirm p16` by option, and a deciding run started without them pays for every arm and can only end NOT EVALUABLE, which is the same reason the anchoring service is checked before the first call rather than at scoring time. The five are not refused for the same consequence, and the refusal says which: without the calibration uncertainty or the slope band a contract-required component has nothing to compare and the result is NOT EVALUABLE outright, while without the horizon, the practical-absence band or the across-window resolution the verdict keeps the name it would have had and the controls component and the refutation rule reach it on evidence the registration does not have. Every paid mode needs the ceiling, not only the deciding one: `smoke`, `pilot` and `confirm` all take `--allowance-gbp` and `--max-call-gbp`, and all three dispatch through a controller that reserves the per-call maximum before each request leaves and halts the run when the remainder cannot cover the next one.

Run it against the simulated system first. The mock obeys the framework's growth equation with a coupling the test knows, so the whole pipeline is proven end to end before a real system is touched:

```
python3 -m arc_runner.cli demonstrate p5                # crossed bank, two routes, seal, held-out, typed pair
python3 -m arc_runner.cli demonstrate p5 --theta 0.2    # the rate-confound world
python3 -m arc_runner.cli pilot p5 --checkpoints DIR --pool-module M --allowance-gbp 40 --max-call-gbp 0.5   # runs, seals, and refuses to score
python3 -m arc_runner.cli demonstrate p16               # driven titration, sealed line, detection rule
python3 -m pytest tests/test_runner_e2e.py -q           # the seven end-to-end proofs
python3 -m pytest tests/test_execution_mode.py -q       # the demonstration-to-confirmation boundary
```

What the end-to-end run found, in the order it found it, because each is a design fact and not a bug. A one-round increment is smaller than a single ladder reading's binomial noise, so readings are repeated and averaged, and a bank with too many unresolved cells is INCONCLUSIVE on the precision condition. The Deming correction with an assumed equal error ratio inflated the coupling, because the increment's error dwarfs the state's; the ratio is now estimated from the bank's own repeated reads, which is the registered rule. A ladder without headroom returned NOT EVALUABLE for every held-out system, which is ruling 29 working. The bank's states must span the range the trajectory will traverse, and the calibrated rate is the binding precision, exactly as the separate simulation reported. The reversal detector's threshold for a growing window is 4.0 rather than 3.0, chosen at the flat null where the per-arm alarm rate was observed near five per cent (an observation whose own interval reaches about eight, which is why the complete family is now calibrated separately: see finding A3 below). And in the rate-confound world the two routes disagree, 0.72 by state against 0.48 by retention, so the bank returns NOT IDENTIFIED while the state-route coupling still predicts the path: the separation the crossed design was built to make, produced by code rather than by argument.

A real run needs three things the mock supplies for free: an adapter pointed at a system (`ARC_RUNNER_MODEL`, `ARC_RUNNER_BASE_URL`, `ARC_RUNNER_API_KEY`; the key is never printed), a domain ladder registered and hashed before any run with headroom to the final checkpoint, and a checkpoint loader that places a system at a capability state. The reference arithmetic ladder is a smoke test of the real path and not a registered instrument, and `confirm` refuses it by name: a loader that manufactures an artefact from a number is refused in the same breath, because a cell placed at a state that was never built is not a cell at that state.

### The apparatus, which is not the custody question

Custody settles whether a record is the record that was sealed and whether somebody outside this code attested it. It is a complete answer to that question and it says nothing about what was measured: a simulated system, read through a checked ladder, carrying a genuine receipt and a named attestation, satisfies every part of it. An earlier version of this package answered the other question in one line by refusing confirmatory collection outright, on the ground that no real assay is released here. That refusal also barred the case the four modes exist to serve, so what stands in its place is the part of it that is true of everything this package can point at: every system shipped here declares itself a simulation, and a deciding run built out of one is refused. A system that declared nothing is refused with it, for the reason an unstated mode resolves to a demonstration and an unstated observed quantity refuses, and it was the gap that mattered most: `confirm` already refused a remote endpoint, because no released assay exists to point one at, so before this the only thing that could reach a confirmatory verdict was a local object that models the world, and the manifest wrote `simulated: false` beside it because that field is derived from the mode word rather than from the system.

The declaration is the caller's statement about the caller's own apparatus, in exactly the way the anchoring service and the prior-inspection attestation are, and it is read from the two conventions this package already had: `metadata()` on a model adapter, which both shipped adapters answer, and the observation spec attached to a margin source, which the assay gate already reads. It is asked twice, and the two catch different runs. `mode._system_refusals` asks before the first paid call, where a refusal costs nothing, and names every system the run holds including the held-out panel's. `manifest.require_released_apparatus` asks at proposition level, where a bundle re-scored from disk long after the gate has gone is read; the declaration is written into the confirmatory inputs before the seal, so it is inside the sealed specification hash, and a record edited afterwards to say the simulator was a real system fails custody rather than passing the release check. The command line's pre-flight is the one caller that postpones the question, because it runs before the adapter is constructed so that an operator learns what is missing without a provider key in the environment; it names the deferral in the call, and the runner asks it of the object it actually holds.

### Custody: the commitment, the identity and the evidence (finding A8)

A seal made in memory, whose only witness is the runner's own clock, is a commitment to nobody. `arc_runner/custody.py` closes that: the seal record's own hash is handed to the operator's anchoring service and the receipt it returns (an identifier plus the sha256 it attests) is recorded on the seal. `require_scoreable` now asks the deciding path for that receipt, refuses one the runner manufactured for itself, recomputes the seal digest and the specification hash before agreeing that either still holds, and compares the predictions and the configuration in hand at scoring time with the ones that were sealed. A prediction edited after the seal, a configuration moved to fit a result, or a run nothing outside the code ever attested, all refuse instead of scoring. This package performs no anchoring: `--anchor-module` names the operator's service, and the only anchor shipped here is a mock that says so in its identifier, its label and a boolean, and is accepted only in a demonstration or a pilot.

The third question the finding names is whether the material deciding the predictions had already been inspected when they were chosen, and no hash can answer it: a digest proves the material has not moved since it was hashed and says nothing about who had read it before. The seal therefore carries a named party's statement, with the digest of the material it speaks about and the time it was made, written on the seal before the anchor and so inside the anchored digest: an attestation added, removed or improved afterwards makes the recomputed digest disagree with the receipt. `--attestation-module` names the module that returns it, `custody.attestation` builds it, and the only one shipped here is a placeholder that attests nothing, labelled in three places, honest in a demonstration or a pilot and refused at proposition level. Where the scorer holds the material, `require_scoreable(..., heldout_sha256=...)` refuses an attestation made about a different artefact. This package composes no part of an attestation, for the same reason it performs no anchoring: an answer written by the party being checked is not an answer. A review of the first version found that it was writing two of them. `attach_attestation` filled the missing fields in with defaults, so a record carrying an attester and a digest and nothing else reached the seal with the shipped sentence written into it and a time read off this code's own clock, and the deciding path then reported a named party's attestation that the named party had never made; `--attestation-module` hands whatever a module returns straight to the run, so the shipped command line reached it. An incomplete record is now refused rather than completed, in every mode, and a supplied record is checked for completeness at the deciding gate as well, where nothing has yet been spent: P5 seals after its bank and its calibration window, so a record refused at the seal would already have cost a run its bank.

Code identity is portable. Paths enter the digest relative to the package root, every entry length delimited, so the same bytes in another directory produce the same identity and an independent analyst can recompute it. The identity binds the ladder spec, and for a ladder that decides items by running code it binds the source of each verifier's module: a pool hash says which items were asked and says nothing about what counted as passing them.

`--out` is now the evidence bundle rather than a manifest file. It names a directory that receives the manifest before the first paid call, the seal with its receipt at the moment of sealing (so a crash between the seal and the last checkpoint still leaves the commitment on disk), and at the end the complete record under an explicit schema: the full bank rows, every ladder read with its subset size and pass count, every held-out replicate series, every P16 arm's margin series, the manifest, the seal, the receipt, the verdicts and the provider metadata the adapter no longer discards, including the model identifier the endpoint actually returned. A P16 run keeps the same record as a P5 one where it is given the same objects: handed the ladder and the adapter rather than a hash and a name, it turns the read log on, so every whole-pool reading a real arm takes reaches the bundle beside the arm's series, and it records the provider's own account of what it served. That ladder is a claim, because P16 does not read the ladder itself but is told which one its margin source reads, and three things check it: a run whose inputs and whose argument name different pools is refused rather than resolved; the object the run binds is the object the deciding gate is shown, so a ladder reaching the seal has been through the rules that refuse a simulated pool, the reference smoke pool and an unattested verifier; and a log attached to the named ladder that records nothing while the arms are collected is the claim failing in the one way anything here can observe, which the bundle states in words and the deciding path refuses after the evidence is written. An empty read list now says which of the three things it means: no log was attached, the log recorded every reading, or the log was attached and recorded nothing. And one manifest may not name one pool in `ladder_sha256` and another in `ladder_identity`, which was possible from the moment the identity stopped being derived from that same string. The bundle is the public artefact: answer keys, hidden checks and anything shaped like a credential are removed by name on every write. `custody.load_bundle` and `custody.recompute_verdicts` reproduce the table from the bundle alone, and `custody.reanalyse_bank` re-estimates the two routes from the saved rows.

### What P16 observes, and in which coordinate (finding A1)

P16 used to take a callback returning one float per round, call it a correction margin, regress it against ordinary round indices and declare a reversal when the fitted slope was negative. Nothing anywhere said which quantity the float was, and the registration's Delta is already the logarithmic slope of the service to burden ratio, so on a series of Delta values that rule tested the wrong thing in both directions: a constant negative Delta, which is the event, has no slope and never fired, while a falling but still positive Delta, which is not the event at all, fired every time. Both halves are in `tests/test_p16_observation.py` on the same numbers, read once undeclared and once declared.

`arc_runner/observation.py` types the boundary. A source declares its quantity, its units, its clock, its estimator and its smoothing window, and the declaration decides the observation model. Delta is read on its level, because the event is where Delta is and not where it is going. log(Q/W) is fitted against log R, the logarithm of the recursive coordinate, and never against the unqualified round number. Q/W is the same case after the logarithm is taken at intake, which is why a round with no offered burden is excluded and counted rather than made to disappear inside a log. The clock and the estimator belong to the quantity and cannot be chosen per run, an unregistered smoothing window is refused rather than given an invented variance, and an undeclared source resolves to the unregistered per-round surplus rate: silence never promotes a series to the registered coordinate.

That settles the two slopes. The sealed line's slope is minus (1 minus chi), being d Delta / d alpha; the reference mock's trend is 0.01 per unit dose per round, being a rate of change of a rate. No conversion between them exists without Q, W and R, so the verdict refuses the comparison by name and says which coordinate it was in, and a run in the unregistered one is refused at proposition level. `mock_balance_source` supplies Q and W separately from the marginal-burden model, so its arms sit on the registered coordinate: each arm's estimate is 1 - alpha (1 - chi), the fitted line has slope minus one half and its zero at two, and the fitted line and the sealed line are then the same object. On the deciding path the assay must supply Q and W separately or the approved sufficient observations, and a source that returns the assumed balance itself is refused: a callback handed back Delta has restated the answer the arm exists to measure.

The real assay does supply them. `code_domain.suite_margin_source` now returns Q, the count of carried faults the round cleared, and W, the count of regressions it introduced, separately and unreduced, with R the artefact's accumulated revision depth rather than the round number, since a high-dose arm spends more revision passes per round and so travels further in R. The four balance objects travel with each reading, and the bundle keeps the readings whole, so an analyst can re-check the ratio against the measurements it came from.

### What P16's support branch has to enforce (finding A2)

The support branch used to count reversals in the above-boundary arms, count non-reversals in the controls, check that the fitted line was falling and that its zero sat within a tolerance of the sealed zero, and declare support. Four registered requirements were sealed, reported or promised and never enforced. `timing_tolerance` was written into the seal and no decision ever read it back, so a response arriving thirty rounds after the manipulation counted exactly as one arriving at the switch. The sealed slope magnitude was printed beside the fitted slope and compared with nothing: the branch asked only whether the line was FALLING, so a line five times too shallow supported the proposition as well as the registered one. The location was a point distance with neither the fit's uncertainty nor the boundary's calibration uncertainty in it. And the arm's ASSIGNED dose served both as the dose the apparatus was asked to deliver and as the exposure the line was fitted against, so a titration whose lever failed reported a line drawn against intentions. Two more requirements were absent altogether: the apparatus's own record that the dose was administered, and the fresh-data repetition the registered rule requires before any single run reads as support.

`arc_runner/p16_components.py` carries the nine components, each decided on its own evidence and its own uncertainty and reported in one of four states: SATISFIED and FAILED are decisions, UNRESOLVED means the measurement was made and its uncertainty does not decide, and NOT SUPPLIED means the run carries no evidence on that requirement at all. **Delivery** is the apparatus's attestation that the assigned manipulation was administered at the sealed switch, an unattested arm being unsupplied evidence and never a defaulted yes. **Realised exposure** is the growth exponent each arm actually reached, measured as the slope of log U on log R, and it is what the balance line is now fitted against; an arm assigned above the boundary whose realised exponent is measured below it fails. **Event** reads the above-boundary reversal rate against the detection rule's own calibrated per-arm false-alarm rate. **Timing** compares the CHANGE POINT, estimated by least squares over candidate split rounds, with the sealed window, and never the declaration round, which is a detection latency: on these worlds a true switch at round 8 is not declared until the high teens or twenties. **Location** compares the fitted zero with the sealed zero as an interval, with the fit's covariance through the delta method and the boundary's calibration uncertainty both in it. **Slope magnitude** compares the fitted slope with the sealed one inside a registered equivalence band. **Controls**, **discrimination** and **repetition** complete it.

The wrapper combines them and refuses. A proposition-level result is withheld while any contract-required component is unsupplied; a failed component withholds support whatever else holds; and a single run is provisional in every direction, reported as AWAITING FRESH-DATA REPLICATION, which is the label `arc_instruments.verdicts.p16_endpoint` returns in the same state. The `P16` key is that wrapper's result. The old branch's own reading is kept verbatim under `run_pattern`, with its five labels unchanged, because it is the run's description of its arms and because the operating-characteristic battery measures the detection rule through it.

Two numbers the contract does not register are unset by default, and the components they gate are NOT SUPPLIED until an author sets them: `chi_hat_se`, the calibration uncertainty on chi, without which the location and slope comparisons would treat the prediction as exactly known; and `slope_equivalence`, the band the fitted slope must be shown to lie inside. Choosing the width of a band that decides a proposition is the author's act, so an unset band refuses rather than defaults. On the deciding path the refusal comes earlier still: the mode gate names them with the ladder and the ceiling, so a confirmatory run cannot start and buy arms whose only possible reading is NOT EVALUABLE.

The demonstration is the exception, and it is an exception in the direction that costs nothing. With no band set the wrapper withholds every result, so `demonstrate p16` reported NOT EVALUABLE and showed nothing of the branch it exists to show. It is now run with the candidate numbers `p16_calibration.py` measures the decision family under, and every one of them is named as a candidate in the sealed configuration, in the verdict block and at the top of the printed summary beside the mode label. A quantity typed on the command line replaces a candidate and is no longer named as one. The deciding gate refuses a titration carrying the label, so a candidate cannot travel from a rehearsal into a run that decides anything, `smoke` and `pilot` are unchanged and carry no number nobody typed, and the demonstration is refused at proposition level exactly as before.

### What a P16 non-alarm means, and what may be refuted from one (finding A3)

An arm that produced no alarm used to read "AS PREDICTED" wherever no reversal was predicted, and a majority of silent above-boundary arms used to read `REFUTED (no reversal)` outright. Both turn the absence of a measurement into a measurement. An arm can be silent for four different reasons and only one of them is evidence against a predicted reversal.

`arc_runner/p16_sequential.py` separates them. A **demonstrated sign** is a margin lying wholly on one side of the registered band on the whole window AND on each segment of it: measured, and positive (or negative), and there for the whole window rather than on average over it. A **demonstrated practical absence** is a terminal interval wholly inside that band with no segment of the window demonstrating a sign outside it: measured, and nil. **Low information** is an interval spanning both: the arm was watched and nothing was learned from it. **Not sustained across the window** is a whole-window reading its own segments contradict, which is neither of the first two and is not low information either. A **censored** observation is an event unobserved by the horizon, because the arm did not run far enough past the switch, or because no informative horizon is registered at all, in which case no length of silence has been said to be informative and every silence is censored. Censoring dominates: an arm that may still reverse has not shown that it will not, whatever its interval says about the margin so far.

`REFUTED (no reversal)` therefore needs demonstrated POSITIVITY in a majority of the above-boundary arms, each beyond the informative horizon: the predicate `arc_instruments.verdicts.p16_prohibition` names, `margin_lower_bound_positive_across_window`, together with `p16_endpoint`'s event absent past an informative horizon. Everything else that fails to reverse is inconclusive, under a label of its own. The event component fails on the same evidence and is UNRESOLVED without it, so a set of arms too noisy, too short or too few to decide anything no longer refutes the proposition exactly as a set of arms measured firmly positive would.

**Across the window, and not on its mean.** One interval on the window mean is a different and weaker predicate than the one the contract names, because a mean is deaf to when the margin was where it was: an arm at plus 0.30 for forty-two rounds and then negative for the last eight, the reversal having plainly happened, has a whole-window interval wholly above the band. Reading that arm as demonstrated positivity is this finding's defect moved from the alarm counter to the terminal reading. So the same window is also read in consecutive equal segments and every segment must clear the band. The resolution is registered by the author, because it is a trade the contract does not settle: a reversal shorter than one segment hides inside it, and a segment too short measures nothing. On this runner's coordinate the second edge binds hard, log R barely moving late in a run; measured on the world whose margin is firmly positive everywhere, halves hold the margin above the band in ninety arms of ninety, thirds in forty-seven of ninety, and at four segments a world with no reversal in it fails, while in the same halves the flat null holds nothing in ninety arms. Two is therefore the candidate registration, its price is calibrated in a world of its own (a reversal confined to the last segment, which a two-segment reading averages away), and the segment length travels with every refutation so that a reader knows which reversals it excludes.

**A practically nil margin is not positivity**, so a registered band is required before anything may refute. With no band the module can only compare the sign with zero, and a noiseless margin of plus 0.001 would then refute the proposition on a measurement saying the margin is nil. The sign against zero is still reported; it decides nothing.

**The controls read their own silences too.** SATISFIED needs no control to have declared AND each control's silence to have demonstrated it. The component used to reach SATISFIED from the alarm count alone, so a run with no registered informative horizon could report that neither the sham nor the baseline arms shifted while every one of those same silences classified as censored: one run, two contradictory readings of one silence, and the generous one decided. An unobserved event is not an absent one in a control arm either.

The sequential rule is frozen as one object and sealed with the line: the growing-window look schedule and the number of looks it takes, the size of the first look, the threshold, the variance estimator, the terminal reading and the resolution it is read across, the informative horizon, the practical-absence band, the control aggregation, and the support and refutation rules. Three of its numbers are unset by default and fail closed for the same reason the A2 bands do: an informative horizon, a practical-absence band and an across-window resolution that decide a proposition are registered by the author, and until they are, no run refutes from silence. A deciding run is refused outright for want of them, before the first paid call, together with a resolution the post-settling window is too short to be read at and a horizon no arm in the titration could reach.

**Temporal correlation.** An arm's rounds are a time series, so an independence standard error computed from its residuals is too small and the growing window declares the event on noise. The registered estimator is Newey and West's with Bartlett weights at Andrews' automatic bandwidth with an order-one plug-in; a moving-block bootstrap of the residuals is implemented beside it as the stated alternative, and which one a run used is recorded, never inferred. The rule reads the larger of the robust and the independence figures, so a variance repair can only widen an interval and can never manufacture an alarm. The fixed rule of thumb was measured and rejected, and the measurement is a test rather than a remark: three Bartlett lags recover about a fifth of the long-run variance of a series correlated at 0.9 (`test_the_fixed_rule_of_thumb_recovers_about_a_fifth_of_the_long_run_variance`), and the repair changes decisions and not only interval widths, removing alarms on an autocorrelated flat null that only the independence assumption supported (`test_the_robust_standard_error_removes_alarms_the_independence_assumption_supported`). Short-window behaviour is part of the same rule, because at four points no variance estimator can see a long dependence; the size of the first look is registered with the rest, the reference rule's four is kept as the default so that this repair changes no run on its own, and the calibration measures what the choice costs (on an autocorrelated flat null, a first look of twenty-four rounds roughly a third of the alarms of a first look of four).

**And the error rate is calibrated, not asserted.** The threshold comment used to report an approximately 0.052 flat-null alarm rate from 400 series as though it were demonstrated control at 0.05. Twenty-one alarms in 400 is an observed 0.0525 whose exact interval reaches 0.079, so the observation is consistent with a true rate half again above 0.05; a rate of zero in 400 is not zero risk either; and a per-arm rate is not the rate of the COMPLETE decision family, which is every look in every arm plus the run-level rules that read them. `p16_calibration.py` runs that family on the candidate registered configuration across seven worlds, being an independent flat null, an autocorrelated one, the same one read with a longer first look, the true world, a world whose margin is firmly positive everywhere and where refutation is the correct outcome, and two worlds that reverse late, one where the registered resolution sees the reversal and one where it cannot; it reports every rate with its exact binomial interval. The last two are the only worlds here that are not constant in Delta within an arm, which is why they are the only ones in which the window mean and the across-window reading can disagree.

### Repeating a deterministic score does not manufacture precision (finding A4)

`read_mean` divided a binomial standard deviation by the square root of the number of repeated reads, whatever ladder was underneath it. On a ladder that redraws a stochastic outcome that is the standard deviation of a mean and it is right. On a ladder that applies fixed verifiers to a fixed item set it is precision made from nothing: the second read of a deterministic score is the first read again, so reading one unchanged artefact 256 times reported a claimed precision sixteen times tighter than reading it once, bought from 255 repetitions that carried no information at all. The reference ladder was also scored by a substring check, which a response enumerating candidate answers satisfies without solving anything.

`arc_runner/sampling.py` separates deterministic verification from measurement uncertainty. Whether an artefact passes item 42 of a frozen pool is settled by running the check: exact, no standard error, and no repeat can make it more exact. What has a standard error is a question about a POPULATION, and a question about a population has no answer until the sampling unit is named, so every ladder declares its unit and the declaration decides the arithmetic. A **fixed form** resamples nothing: the error is zero, which is not a claim of certainty about anything broader but the statement that the reading is exact conditional on that item set, and that this ladder samples no wider population. An **item form** drawn without replacement from a frozen pool carries the finite-population sampling error of that draw against the pool, so a subset read is not binomial with the subset as its own denominator and a whole-pool read has no sampling error at all. A **stochastic execution** keeps the square root of the read count, which it earns. An **artefact or process repeat** is a legitimate assay unit, but no ladder supplies it, because a ladder reads the artefact it is handed and cannot resample it; in this runner it is supplied above the ladder, by P5's replicate continuations from the one sealed checkpoint.

Silence fails closed: an undeclared ladder is read as a deterministic fixed form, so it cannot manufacture precision by omitting to declare a unit. A confirmatory run refuses an undeclared unit outright, because which population a deciding run measures is stated rather than defaulted. The unit goes into the ladder spec and therefore into the ladder hash and the seal, so a run scored under one sampling model having sealed another is a custody failure and not a silent change of estimand.

And the declaration is never taken on trust, because a declaration alone is also what a deterministic ladder mislabelling itself as stochastic has: under the first repair such a ladder was handed the square root again, and five identical scores of 20 were reported at 3.16, 0.79 and 0.20 for 1, 16 and 256 reads, which is the finding's own headline arithmetic returning through the label. The reduction is now earned by the readings. Every reading carries the identity of the form it drew beside its count, and readings that are identical in both are one reading counted many times whatever the ladder calls itself: the per-read error is reported undivided, so 1, 16 and 256 repeats claim the same precision. Two different item forms that happen to count the same passes are still two draws, which is why the form and not only the count is compared. Before a deciding run starts, a ladder claiming independent repeats must also SHOW what one read would draw afresh: `resampling_witness` reads no artefact and spends nothing, and a ladder whose witness is absent, unreadable or constant is refused at the gate. A whole-pool item form is exempt, because it claims no reduction at all.

The substring refusal is read through wrappers, and beyond that a check must attest what it is. `functools.partial(contains_answer)` and a `functools.wraps` wrapper are new callables carrying no mark of their own, so the marker is followed through a partial, a wrapper and a bound method; a one-line lambda delegates to nothing that can be followed, so the deciding path asks every check to attest with `custody.attest_exact_check` that it decides whether an item was SOLVED, and refuses what attests nothing. An unmarked wrapper around a smoke check is indistinguishable from an unmarked measurement, and re-attesting a wrapper is the deliberate act custody is made of.

The check is refused separately from the pool. The reference arithmetic pool and the reference arithmetic ladder are both smoke-only and both barred from confirmation, and beyond that a substring verifier is refused wherever it is attached, including to a registered pool, because barring the pool leaves the check free to be reused behind a better one. `contains_answer` is kept and marked rather than deleted, since a wiring smoke test is a legitimate use of it and deleting it only invites somebody to rewrite it unmarked. The reference ladder is now scored by `exact_answer`, which requires one answer line labelled with the item's own identifier and exactly the right value on it: two answers for one item fail the item, because a response that gave two answers did not give this one. (That reference ladder had never once been called: its item generator asked numpy for an integer in an empty range and raised on its first item.)

Where the reading is exact the errors-in-variables step has nothing to correct, so P5 takes the limit the correction names, which is ordinary least squares, rather than a ratio manufactured from a standard deviation the read does not have. The bank records the sampling unit beside its rows, because pass counts with no statement of what they sample cannot be re-analysed by anybody, including their own authors a month later.

### P5's correlated before-and-after error, and its positive-increment filter (finding A5)

The bank measured a state, ran one round, measured again, and handed two DERIVED numbers to a regression: an available capability equal to the retention fraction times the before reading, and an increment equal to the after reading minus the before reading. The before reading is inside both. Its error entered the predictor with a plus sign and the response with a minus sign, so the two axes carried a covariance by construction, and the estimator was an errors-in-variables correction parameterised by a single ratio of two error variances, which has nowhere to put one. The same code also divided the read standard deviation by the AVAILABLE capability rather than by the before reading, so at a fifth retention it overstated the predictor's relative error five times over.

The second half was what the code did with the increments it did not like. Before taking logarithms it removed every cell whose increment was not positive, counted the removals, and declared the bank inconclusive only if the count passed a ceiling. A cell is removed exactly when the read noise ran downwards further than the round grew, so the rule kept the upward errors and discarded the downward ones, and it did so hardest wherever the increment was smallest beside the read error, which is a position on the very axis whose slope was being measured. On a bank whose true increment did not depend on the available capability at all, the surviving cells carried a fitted exponent of plus 0.12 against a truth of zero; on a bank with no growth whatsoever, they carried one near 0.28. A genuine regression, a genuine zero and a genuine decrement were all deleted by the same rule, which reported them as cells the ladder could not resolve: an inconvenient outcome had become a generic measurement failure.

`arc_runner/p5_observation.py` fits the observation model to the ORIGINAL PAIRED READINGS. The joint density of the before reading and the increment given it is written down and maximised: the increment's conditional mean carries the before error with the coefficient the subtraction gives it, its conditional variance carries the process variability, which scales with the size of the increment, and the after read error; the retention fraction is handled as the exact quantity it is; and the latent capability state is one parameter per state, because the placement loader places the same artefact for every replicate, an assumption the fit checks against the within-state scatter rather than assuming. A read error correlation is declared by the ladder and sealed with it, because whether the two reads of a cell share their item form decides how much of the common error survives the subtraction; zero is the fail-closed default because it is the wider reading. Standard errors come from the observed information sandwiched by the row scores, and the analytic gradient is checked against central differences.

Nothing is dropped, so nothing can be dropped selectively: a zero increment and a negative one are observations. What the fit will not do is report an exponent it cannot support. A rate not distinguishable from zero is reported as NO MEASURABLE GROWTH, because there is no elasticity of an increment that is not there; a negative fitted rate is reported as a decrement whose exponent is measured and whose process the registered growth law does not describe; a saturated subset with no residual degrees of freedom is refused rather than fitted. Over two hundred simulated banks of the registered shape with a true exponent of one half, the paired fit returned 0.5007 with a spread of 0.0158 and 184 of its 200 intervals covering the truth against a nominal 190, while the estimator it replaces returned 0.5115 with a spread of 0.0231, being both further out and half again as scattered. The log scale estimator is kept as a labelled diagnostic in every run's record, with the covariance term, without it, and with the Deming slope the runner used to report, so the size of the repair is visible; it is not the primary, because it still cannot take the logarithm of a nonpositive number and because its transform's second order tilt is not removed by any first order correction: on those same two hundred banks the covariance corrected log scale slope returned 0.5123 and the same slope without the covariance term returned 0.5113, so the covariance is worth a thousandth and the transform's own tilt is worth twelve.

H2's precision condition is unchanged: it still counts the cells that came back nonpositive, because a repair to an estimator is not a licence to restate a registered threshold. What changed is that those cells are then fitted rather than deleted. The model's own expectation of the same fraction is reported beside the count, and which of the two the registered ceiling should be read against is named in the code as the author's decision.

### Two regression directions are not two interventions (finding A6)

The runner's two routes are the response to the capability state at fixed retention and the response to retention at fixed state. When those two numbers came out within a fixed distance of each other, and the negative control showed nothing, the run printed IDENTIFIED. Three separate things were wrong with that, and they are three separate repairs.

The first is what the two directions are. Nothing was manipulated twice: one bank was measured once and two slopes were taken through it in two directions, sharing every cell, every artefact and every read. The charter's identification asks for two ways of CHANGING CAPABILITY, one of which does not run through recursion, so that agreement between them says the elasticity belongs to capability rather than to the pathway that produced it. Two slopes through one bank cannot say that however closely they agree.

The second is what agreement between them means. The reference mock wrote the increment as a power of the available capability, `(f*U)**beta`, which builds into every clean world the assumption that the elasticity in the retention fraction and the elasticity in the capability state are the same number. In the general process `a * f**theta * U**beta` they are separate, the state direction estimates beta and the retention direction estimates theta, and their gap estimates theta minus beta. The mock now takes `retention_exponent`, so that world can be simulated, and the crossed fit in `p5_observation` estimates both exponents together: on a bank with theta at 0.9 and beta at 0.5 the single-exponent fit returns 0.60, which is neither, and the crossed fit returns 0.47 and 0.89. It also takes `available_rate_exponent`, a nuisance rate scaling with the available capability, which adds the same amount to both elasticities: the two directions then agree exactly at 0.7 while the coupling is 0.5. Agreement without identification is a world, not a hypothetical, and both are rows in the runner battery and cases in `tests/test_p5_identification.py`.

The third is the arithmetic. The gap was compared with the margin as a POINT, so a bank with a standard error of a third and a gap of a hundredth was reported as agreed, which is a statement about the bank's imprecision rather than about the quantity. The comparison is now a two one-sided tests equivalence read through the REGISTERED interval convention in `p5_prediction`, which is the ninety per cent two-sided interval with strict clearance, and the gap is estimated ONCE as the crossed model's excess retention exponent, with its own standard error, rather than differenced between two fits that share every cell and therefore have a covariance no difference of two standard errors can carry.

So the run reports two things where it used to report one. `ROUTE_AGREEMENT` is CONSISTENT, INCONSISTENT or UNRESOLVED and is never the word IDENTIFIED. `IDENTIFICATION` is a separate judgement in `arc_runner/p5_identification.py`, and it reaches IDENTIFIED only on an independent capability manipulation supplied by the domain: a second way of placing the capability state that does not run through retention, declared as such, carrying a written exclusion restriction and an estimate of the capability elasticity that agrees with the bank's inside the same equivalence, with the negative control showing no material coupling. An undocumented manipulation is refused BEFORE its bank is run, so an inadmissible intervention is never something a run has already paid for. With none supplied the judgement is NOT ESTABLISHED and says in words what is missing, and the command line prints that sentence above the summary the way the mode label is printed.

An inconsistent pair of directions is no longer read as a refutation of the mechanism. A capability mechanism whose channel is not retention alone produces exactly that pattern, and the finding is explicit that it must not be rejected for it: with a documented second channel that agrees, such a run reaches IDENTIFIED, and without one it reaches NOT IDENTIFIED with the reason saying that the bank holds two readings and nothing in it chooses between them. Which elasticity the sealed prediction uses is a precision question and is now keyed on the consistency check rather than on the word IDENTIFIED, because that word has changed its meaning; the rule itself is the registered one and is unchanged, being the pooled fit when the two directions are consistent and the STATE route when they are not, since the held-out continuation runs at full retention and therefore travels along the state. The crossed fit's capability exponent is reported beside it under its own name and is not used: it estimates the same quantity and would be a defensible amendment, and the estimator a sealed prediction is built from is the author's to change.

A later review of that repair found five defects in it, and each is now a case in the same file. The equivalence written into `p5_identification` read a CLOSED boundary, `abs(point) + half <= margin`, while the registered convention reads strict clearance, so on a gap of 0.125 with a half width of 0.125 against a margin of 0.25 the registered comparison returned unresolved and this one returned CONSISTENT and the judgement built on it returned IDENTIFIED; every equivalence in the file now goes through the convention object itself, and the level and multiplier are read from it rather than declared a second time. The judgement read admissibility off a `documentation_failures` key in each record, so a record carrying an empty list and no description at all reached IDENTIFIED, and a saved bundle re-scored to its own label rather than to its evidence; admissibility is now re-derived from each manipulation's own description at the moment the word is produced. A manipulation could place its cells with the BANK'S OWN loader and be counted as a second channel, differing from the bank in nothing but two declared booleans; that one case needs no domain knowledge and is refused, an unperformed comparison fails closed, and the manipulation's adapter is named in every record. The set of manipulations sat outside both the sealed specification hash and the deciding gate although it had become the only route to IDENTIFIED; the descriptions are now inside the manifest's configuration before the first paid call, and the gate checks their documentation and reads their loaders back against the checkpoint store exactly as it does the bank's. And an estimate supplied instead of a bank must now carry a written provenance, because a number typed into a mapping and a number measured elsewhere are otherwise the same object.

### The final comparison keeps every assigned system and the full uncertainty (finding A7)

The sealed prediction and the held-out observation were compared by an arithmetic that dropped most of the uncertainty on one side and part of the population on the other. Three separate defects, and they are three separate repairs, in `arc_runner/p5_prediction.py`.

The first is the prediction's own uncertainty. The predicted exponent is a function of three measured things: the coupling the bank estimated, the rate calibrated from the system's own window, and the starting state read at the last calibration checkpoint. The old width moved only the COUPLING, to the two ends of its interval, and re-calibrated the rate at each end from the same calibration readings, so those readings entered the width as though they were exact and the starting state, which is one of them, never moved at all. On the runner's own clean world that is not a small omission: the calibration window supplies more of the prediction's spread than the bank does, at 0.012 against 0.009 on the three-system demonstration, and the joint width comes out larger than the endpoint width even though it is read at the ninety per cent level while the endpoint width was read at ninety-five. The propagation now resamples the coupling, every calibration reading and the starting state JOINTLY, so that a window read high raises the start and the fitted rate together and the cancellation between them is the one the world has. A calibration error shared across a system's readings, being a bias rather than read noise, is a field on the convention and reaches the interval the same way; it does not cancel, because it shifts the start while leaving the fitted rate almost unmoved. A resampled window containing a reading at or below zero is outside the support of a pass count, so it is counted and refused rather than evaluated into a not-a-number that vanishes silently.

The second is the coupling's domain. The old width clipped each end of the coupling's interval into [0, 0.95] without saying so. A clip is a claim that the coupling sits at the boundary, it reports a narrower interval than the bank supports, and it hides that the interval reached the boundary at all. The domain is now named in one place and enforced: draws outside it are counted rather than moved, the record says what fraction fell outside and that the reported interval is therefore a LOWER BOUND on the prediction's uncertainty, and a system whose prediction reaches the boundary is reported unresolved rather than scored against a prediction the runner cannot represent.

The third is the difference. The observed-minus-predicted interval used the observed replicate standard error alone, so a system with three tight continuations and a loosely pinned prediction was compared as though the prediction were exact: a narrow prediction gate makes the remaining prediction uncertainty smaller than the margin, which is not the same as making it zero. The two variances are combined, with an explicit correlation term carried with its sign and zero by default because the two sides share no reading, and the multiplier is the LARGER of the replicate t quantile and the equivalence multiplier, so that adding the prediction's uncertainty can only widen the interval. A prediction whose uncertainty could not be propagated at all is refused rather than treated as exact, which is what a non-finite half width used to mean here.

Every assigned held-out system keeps its weight. A system that reached the ladder ceiling was labelled NOT EVALUABLE and then skipped before the denominator was counted, so a panel of five of which three reached the ceiling could be declared supported by a majority of the two that did not, which decides the proposition on a population chosen after seeing the data. The panel is now written into the manifest's configuration and therefore inside the sealed specification hash, the aggregate rule is stated over the ASSIGNED panel, and a system that could not be evaluated, or that never reported at all, keeps its place in that denominator as NOT EVALUABLE. A panel none of whose systems could be evaluated is NOT EVALUABLE; everything else that is not a majority is INCONCLUSIVE. The command line prints the denominator with the result.

The size of all three repairs together, measured on the battery's own worlds over twenty seeds at the registered configuration, AND THE SEED BASE IS PART OF THE MEASUREMENT. Twenty runs pin a rate to about a tenth either way, so a figure quoted without the seeds it came from is not a figure anybody can check: the counts below are given at seeds 2000 to 2019, which is where they were first measured, and at the battery's own seeds 1000 to 1019, which is what `runner_battery.py` reproduces. The old arithmetic is reconstructed from the endpoint half width every run still carries as a diagnostic, scored the way the finding describes it: the survivors alone, the observed replicate spread alone, and a closed boundary. On the true world nothing changes: twenty runs of twenty reach SUPPORTED under both arithmetics at both bases, because a design adequate to the question is adequate to the wider interval too. On the REGIME CHANGE world, where the bank measures a coupling of 0.50 while the held-out panel evolves at 0.35 and P5 must therefore NOT support the prediction, the old arithmetic reported SUPPORTED in twenty runs of twenty at both bases, and the new one in four of twenty at seeds 2000 to 2019 and seven of twenty at seeds 1000 to 1019. On the cheap-ladder world, where the calibration readings carry real error, the old arithmetic reported SUPPORTED in fifteen of twenty at the first base and sixteen of twenty at the second, and the new one in none at either. The battery's P5 rows now carry the panel's own bookkeeping beside every rate, since a panel result cannot be read without the rate at which systems left the comparison.

The denominator has to have been committed to as well as counted. Keeping every assigned system repairs the arithmetic and leaves one door open: where the assigned list is itself reconstructed after the run from the systems that produced a fit, every one of them is counted, the arithmetic looks right, and the population is still the survivors. The panel record now says where its denominator came from, the sealed configuration, the run's own held-out record or an inference made afterwards, and an inferred one keeps its counts and loses the proposition-level word: it reads INCONCLUSIVE with a note saying what it would have read and why it does not. Nothing on the `run_p5` path reaches that case, because the panel is written to both surfaces before any verdict; it exists for a bundle sealed before the panel was, and the command line prints the provenance whenever the denominator was not frozen.

The panel is the table as well as the count. The aggregate counted an assigned system that never reported, which is the arithmetic the finding asks for, but the per-system table was written over the systems that produced a fit, and the table is where a reader sees a system's status: a system missing from it has been dropped wherever anybody actually looks. Every assigned system now has a row, an assigned system that produced no fitted exponent has one saying so, and a system scored WITHOUT being on the sealed panel has one marked as not counted, because the population may not shrink and it may not grow. The command line prints both. The propagation also reports the Monte Carlo error of its own standard error, and the gap between the point prediction the difference is read against and the mean of the resampled predictions, which is not zero wherever the solution is curved in the coupling; neither decides anything, and a width quoted to more decimal places than its draw count supports is a precision the calculation does not have.

The interval level and the boundary convention are in one configurable place, `p5_prediction.REGISTERED`, from which every `P5Config` default is read. The registered choice is the ninety per cent two-sided interval, being the interval a two one-sided tests procedure at five per cent reads, with STRICT clearance: an interval that lands exactly on the margin has not cleared it, and the same rule governs the coupling domain. The rule this replaces read `<=` and called exact contact agreement. On the deciding path the convention is gated with the rest of the configuration, before the first paid call: a confirmatory run may hold itself to more than the registered convention and may not hold itself to less, so a closed boundary, a smaller multiplier, a wider coupling domain, a larger excursion tolerance, a resampling count below the registered eight hundred and a positive prediction-observation correlation are each refused by name. The draw count is in that list on the same criterion as the rest and not merely as a well-formedness check: the half width is a standard deviation estimated from those draws, and a small count reports one that is biased low and widely scattered. Measured over twelve seeds of the same propagation, two draws give a mean half width of about 0.054 against the registered 0.091 and are narrower on eleven of the twelve, which is a run buying clearance with simulation noise. A gate written only against well-formedness refuses one draw and lets fifty through, and fifty is the weakening. A larger count than the registered one passes, because more draws can only sharpen the estimate. A configuration carrying none of those fields is under the registered convention already and passes untouched. Whether a recorded resolution should be allowed to license a weaker convention is the author's decision, named in `mode._convention_refusals` rather than taken there.

### What the tree contains, and what it does not (integration, 6 September 2026)

The nine findings above and the repairs from a review of the same code were developed on
two branches at once, and this is the tree in which both landed. What follows is a list of what is
actually here, so that a reader can check the claim against the files rather than against this
paragraph.

Present, and reachable by the names given. `arc_runner/evidence.py` writes, verifies and replays a
LOCAL evidence bundle: three files under one directory, a sha256 for each member and a root digest
over the set, an explicit evidence label and an empirical verdict of NOT TESTED that the writer
refuses to write as anything else. Its replay re-scores a saved run from the observations it saved,
with no provider call and no trajectory regenerated: for P5 it re-estimates the routes from the saved
bank under the saved analysis stream and re-fits every held-out replicate from its stored readings,
and for P16 it recomputes each arm from its measured series through
`arc_runner.p16.diagnostic_verdicts`, which is the registered decision rule reachable without the run.
`arc_runner/p16_contract.py` is a typed component adjudicator, additive and called by neither runner.
`requirements-test.txt` pins the versions the suite was actually run under.
`docs/P16-STAGE-ONE-BRIEF.md` is a stage-one plan whose result shell is deliberately unfilled.

What the local bundle is NOT. It is not the run's own evidence bundle: `--out` names a directory that
`arc_runner.custody` fills as the run proceeds, and that is the artefact a real run leaves. The local
bundle is a second, smaller record with its own schema, useful because it can be replayed by anything
that can read JSON. Its hashes detect accidental alteration and nothing more: a party willing to
rewrite the data and the hashes together is not excluded by them, and an independently held root
commitment remains a separate requirement for a deciding study.

Two vocabularies for one object. A run's readings are exported under both `verdicts` and
`diagnostics`, which address the same object, with `evidence_status` and `empirical_verdict` beside
them. A key name has never said what a reading is; the mode does, and the mode is printed first.

There is no gate in this package that stops a person running it, and this README claims none. The
refusals are library refusals: a remote endpoint is refused where a run is constructed, a
proposition-level reading is refused unless the custody chain holds, and an existing `--out` path is
refused before any compute rather than after the run has been paid for. All of them are in the code
and all of them are in the suite.

The tree's own receipt: `python3 -m pytest tests/ -q` from this directory passes 515 tests with none
failing, on Python 3.9.6 with numpy 2.0.2, scipy 1.13.1 and pytest 8.4.2. The battery's operating
characteristics for this tree are in `instruments/evidence/2026-09-06-runner-battery-a1-a9`, produced
by `python3 runner_battery.py --out <dir> --seeds 2`, with a manifest carrying the sha256 of both
output files and of every source file here. Two seeds per row is a check that the code runs and
reports; it is not a measurement of a rate, and the interval columns say so.
